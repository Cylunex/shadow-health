# 全功能逻辑走查与修复

本轮对当前 Health 代码做三轮检查：正常使用路径、数据/权限边界、后台与失败恢复。
采用本机隔离 PostgreSQL 和合成数据，不接触生产健康记录，也未部署、推送或发布 APK。

## 第一轮：页面与日常流程

- 检查首页开秤、接收状态、活动/睡眠/饮食概览，趋势与展示/录入独立设置。
- 检查饮食记录、食物库、常用组合、照片识别与确认，运动/计划/计时器/体测。
- 检查自律、习惯、化验档案、日/周/年报告、设置、导入、AI 与健康助手。
- 自动访问 35 个页面/片段入口，并从渲染结果提取站内链接和延迟加载地址逐个检查。
- 修复 AI 页面不能接回已有分析任务；新问题提交成功后更新请求键，避免下一次同内容请求错误复用旧草案。
- 修复草案确认后首页 Agent 同步状态仍旧；补充 Agent 已确认来源标签。
- 增加最近审核回执，离开确认页面后仍可找到结果；旧草案可跳转到新版。
- 提醒配置回显当前模式，默认关闭不再显示成“开始观察”。

## 第二轮：数据与审核边界

- 审核原记录必须重新读取加锁后的数据库值，不能使用 Session 中的旧对象；双连接测试覆盖并发修改后拒绝批准。
- 过期/旧版/依据变化草案可重新核对，仍需显式确认；修订/重新核对重复提交返回同一新稿。
- 餐次/日期修订只在批准时同步照片位置，未确认前不移动原照片；已有记录的更新保留日期并说明手动调整入口。
- 待处理查询先按主体筛选再分页，其他浏览器主体的大量草案不会挤掉当前用户的数据。
- 数据源权限/换源只影响真正使用该来源的指标；撤销健康连接不会隐藏手工或体脂秤证据。
- 旧证据确实使用了撤销来源时仍隐藏；行动回看的基线/结果也执行同一撤销检查。
- 历史非有限数值视为缺失；平均值差在最后一步舍入。
- 体测全表单校验后再保存，拒绝 NaN/无效或未来日期，避免错误反馈伴随部分入库。
- 化验不同单位分组展示；换单位不套用默认单位的参考值，不进行自动换算。
- 化验参考上下限、批量重复项目、空值/异常值校验；批量失败保留预览且一行也不保存。
- 化验 OCR 增加图片大小/类型与响应结构检查；名称只精确匹配词表，避免模糊包含关系误合并项目。

## 第三轮：任务与异常恢复

- 周提醒延后一日后仍对应原周，不因不再是配置星期而消失；忽略后不再产生本次任务。
- 页面读取时重新检查安静时段、暂缓和最新同步条件，后台缓存不能让过时提醒继续显示；首页每分钟刷新。
- 领取任务时跳过已耗尽的任务，不阻塞后面的任务；取消/重试/完成/失败清理相应租约和时间状态。
- 达到重试上限后不再显示无效按钮；GET 任务/证据页面不持有写锁。
- 单项监测异常通过保存点隔离，不阻止其他监测和过期快照清理。
- 失效证据可按原窗口重建；原快照已清理时从所属任务恢复窗口元数据，不恢复被删除的健康内容。
- 同一行动重试不因之后的证据变化而重复创建；空白感受不写入。

## 验证与边界

- 完整 pytest 回归通过（最终用例数见提交说明），新增页面与异常路径用例集中于 `tests/test_logic_walkthrough.py`。
- 既有回归同时覆盖：开秤关联/去重、跨日睡眠、多源归一化、游标/迟到/删除事件、离线数据、习惯否决与补卡、饮食营养、展示录入设置、鉴权和 MCP/Nexus 合同。
- `git diff --check` 通过；所有测试仅在本机测试库运行。
- 本轮无数据库迁移、Android 修改和新增外部服务。复盘算法版本升为 v2，旧 v1 快照提示重新生成，不自动改写历史。
- 未连接真实秤/手机、NAS、生产 Platform、模型供应商；真实蓝牙/网络重试、识图准确率和连续七天监测仍属于现场验收，不能由逻辑测试替代。
