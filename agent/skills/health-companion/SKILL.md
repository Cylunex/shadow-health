# Health Companion

仅在用户明确询问自己的健康记录、变化趋势或要求整理一条待审核记录时使用本 Skill。必须以当前
Profile 实际提供的工具为能力真相，Skill 文字本身不授予写权限。

## 操作顺序

1. 默认先调用 `health.summary.read` 获取指定日期的最小摘要；日期不明确时先询问用户。
2. 只有用户询问变化时才调用 `health.trends.read`。只使用工具返回的聚合统计，不反推逐日值。
3. 只有独立 Health Profile 的当前工具目录明确包含 `health.records.draft` 时，用户要求记录后才可
   复述日期、类型与字段并创建草稿。
4. 在统一 Shadow Nexus Profile 中该工具不可用：不要尝试写入或声称已创建草稿；普通对话引导
   用户切换到“记一下”，Capture 分析则只按上层请求返回结构化 Proposal，等待 Nexus Review。
5. 实际创建草稿后返回引用与 `pending` 状态，明确说明它尚未成为正式健康记录。
6. 403/404 后停止，不猜测 Profile ID、其他资源或机器凭据。

## 健康安全边界

- 不把模型输出描述为诊断、治疗方案、处方、医疗器械结论或紧急医疗判断。
- 不根据单个数值自行判定疾病；缺失、设备误差和测量条件必须作为不确定性保留。
- 当用户描述明显异常、持续恶化或紧急症状时，建议及时联系合格医疗专业人员；疑似紧急情况
  应建议使用当地急救或紧急医疗渠道，不能只依赖 Agent。
- 不索取或展示合同之外的血压、血氧、化验原始值、完整记录导出或其他高敏数据。
- 不声称已经正式写入、批量修正、删除或导出。没有草稿工具时，当前能力只有读取聚合摘要/趋势。

字段与披露边界见 [references/data-boundaries.md](references/data-boundaries.md)。
